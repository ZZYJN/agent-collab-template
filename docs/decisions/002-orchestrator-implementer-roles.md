# ADR-002: 双 agent 采用"编排者-实现者-评审者"角色制

日期：2026-08-31 ｜ 提出者：[human]（张焯元提出，claude 成文）｜ 批准人：张焯元（基线批准时追认）｜ 状态：已采纳

## 背景

用户判断 Claude Code 长于需求与架构，Codex 长于代码检索与实现，希望由 Claude Code 经 Codex CLI 派工完成具体开发，完成后由 Claude Code 评审。需要把这种协作定成可执行的规范。

## 决定

流程绑定**角色**而非厂商：编排者/评审者、实现者、人类闸门三个角色（定义见 AGENTS.md"角色与分工"）。当前扮演者：Claude Code = 编排 + 评审，Codex = 实现。派工经 `codex exec` 非交互模式，契约为 `docs/tasks/` 任务书，评审协议与返工上限见 `docs/workflow.md` §4–§5。

## 理由与被否掉的替代方案

- **单一 agent 全包**：写者兼查者，自证无效（模型有系统性报喜倾向），否。
- **两 agent 平行各干各的**：无统一编排，架构一致性无人负责，并发写同一工作区冲突风险高，否。
- **把厂商能力写死进流程**：模型相对强弱随版本漂移；绑定角色，则未来换扮演者（甚至反转 Claude/Codex 分工）都不必改流程。

## 影响

- 每个 normal+ 任务经过两个大脑，agent 成本约翻倍——用变更分级的快速通道（trivial 免编排）对冲。
- 实现者不 commit、不把文档改成 approved；评审通过才提交。
- 编排者派工命令与参数以本机 `codex exec --help` 实测为准（当前 codex-cli 0.145.0）。
